# Judge walkthrough

Use the deployed prototype link provided separately in the competition submission, or rehearse locally with the README instructions. The repository intentionally omits the actual hosted/API addresses. Check the UI mode: `npm run dev:live` uses Gemini; `npm run dev` uses explicit scripted fixtures. Never present fixture results as live inference.

1. Choose **Start demo session**, then **New incident**. Enter a fictional report, or record/upload a fictional voice report. After stopping the recording, wait for transcription, review the editable text and reported location, and only then choose **Start conversation**. A physical microphone requires browser permission; transcription sends the recording to Gemini before incident creation.
2. Use a fictional report of an employee threatened with a knife at the Bengaluru Operations Center parking area, with a minor arm injury and a suspect who fled toward the east entrance. Observe progress states, then the validated reply and provisional service suggestions. Exact questions and classifications can vary.
3. Answer the actual current clarification, including **Unknown** where appropriate. Check the incident report's Yes/No/Unknown indicators, reasons, source quotes and unresolved gaps. Correct the location in chat to demonstrate updates without removing earlier messages. **Finish assessment now** closes intake with remaining unknowns; later updates do not restart it.
4. Open **Review and decide**. Check the prefilled summary, urgency, location and service selections. GPS attached at intake defaults the review coordinates; map selection or human edits take precedence. Confirm the incident location only after checking it. Nearby-service Maps links support manual search/selection, not an automatically chosen nearest available responder.
5. Review the per-service SMS previews, then choose **Approve & simulate dispatch**. It saves and approves in one action. **Save draft** is optional. The popup lists the saved simulated recipients. Show the receipt and clarification history after reload. A no-service assessment needs a deliberate human service choice for approval, or **Close report**.
6. Open a service's incident view from the simulated outbox. It shows the reviewed report and source/clarification history. This currently requires the original authenticated demo session; a different browser/session cannot access it. Independent responder access remains pending.
7. Optionally show **SOS — immediate help**. It opens the reviewed assistance brief and a separately activated phone link. The application has not sent real SMS or dispatched a team. Reset the demo session when finished.

Try **Unclear noise outside** to contrast an ambiguous report. In fixture mode, use documented sample replies from [the conversation guide](conversations.md); unsupported free-form input receives an explicit limitation message.

A failed live validation remains unpublished. The original report is retained for retry or manual review; do not switch to scripted output while presenting it as live inference. Provider rate limits occurred during one repeat hosted check; live availability and latency can vary. See [evaluation boundaries](evaluation.md) for coverage and limitations. Physical microphones and representative accents/languages require further validation.
